## 1. 项目重构与收尾复盘

WeldSnap 项目已完成从 V1.0（Express + 本地 exports/ 存储 + Cookie 会话）到 **V2.0 现代云原生架构** 的全面升级与收尾。

### 1.1 架构升级对比

| 模块 | V1.0 架构 | V2.0 生产架构 |
| :--- | :--- | :--- |
| **应用框架** | Express.js 单体后端 | Next.js 15 App Router 全栈响应 |
| **数据库** | SQLite (`sqlite3` 异步) | `node:sqlite` 原生 `DatabaseSync` + 同步事务锁退避 |
| **照片存储** | 本地 `exports/` 磁盘目录 | 阿里云 OSS 浏览器预签名 URL 前端直传 |
| **视觉规范** | ad-hoc 简易 HTML/CSS | IBM Carbon Design System (Tailwind CSS v4 硬约束) |
| **日志与审计** | console.log 散落日志 | Pino + AsyncLocalStorage (`traceId`) + Level 35 业务审计 |
| **外部集成** | 仅支持手动 Excel 导入 | 致远 OA DEE REST 自动化双向数据同步与状态更新接口 |

## 2. 核心功能与关键模块交付明细

### 2.1 施工现场端 (`/upload`)
- **设备指纹简易登录**：前端使用浏览器指纹免密自注册，重名自动追加 `#0001` 4位数字后缀，且在主界面支持一键 **“修改姓名”**。
- **极简三列工序卡片**：适配移动端大触控目标，分为组对、打底、盖面三道工序，提供直观的已上传/待拍摄/不合格驳回状态。
- **连续扫码与切口定位**：支持通过扫码直达特定管线，提供“上一个焊口”与“下一个焊口”连续顺畅切换。
- **Canvas 前端瘦身直传**：手机端拍摄后就地进行 1920x1080 等比缩放与 JPEG 压缩（由 5-10MB 降至 500KB 以内），直传 OSS，零服务器中转负担。

### 2.2 管理控制台 (`/admin`)
- **三层关系树状管理**：项目 (`projects`) ➔ 管线 (`pipelines`) ➔ 焊口 (`weld_records`) 关系明确。
- **工序进度矩阵与 Hover 预览**：可视化高密度表格，鼠标悬停已上传标签即可通过 OSS 60s 短效签名预览图片。
- **驳回重传与历史比对**：管理员标记不合格照片并附带驳回原因，施工端即时显示红色高亮并提供历史对比预览。
- **零负载客户端打包导出**：前端使用 `jszip` + `file-saver` 并发从 OSS 拉取照片打包下载 ZIP。
- **定制化 27 列标注质量管理 Excel 导出**：流式后端生成含照片缩略图的标准化 Excel 报告。

### 2.3 致远 OA DEE 自动化接口
- **项目同步接口** (`POST /api/sync/projects`)：以 `construction_no` 为主键自动去重新增，支持中英文双语字段名。
- **完工状态更新接口** (`POST /api/sync/projects/status`)：以 `construction_no` 为主键更新完工状态。
- **DEE 脚本适配**：提供 Groovy 脚本解包范例，解决 DEE REST 适配器无法直接引用 Document 节点的避坑方案。

### 2.4 全链路日志与审计
- **全链路追踪**：`withTrace` 包装器为每个 HTTP 请求注入 `traceId`。
- **全覆盖业务审计**：用户登录、简易账号注册与改名、项目新增/删除/修改、API/Excel 导入、状态更新、照片驳回/删除、日志与报告导出均记录 **Level 35 (`audit`)** 日志，支持后台按类型一键筛选与导出。

## 3. 关键技术踩坑与解决方案总结

### 踩坑 1：SQLite 同步并发锁冲突 (`node:sqlite`)
- **现象**：Next.js 并行路由构建及并发请求可能导致 SQLite 数据库文件锁冲突。
- **解决**：在 `src/lib/db.js` 初始化阶段实现了指数退避重试机制（100ms × 5 次），确保事务锁安全释放。

### 踩坑 2：Tailwind v4 CSS 坍缩层陷阱
- **现象**：在 `globals.css` 中添加 Unlayered 的 `*` 选择器重置会覆盖工具类，导致布局坍缩。
- **解决**：移除 Unlayered `*` 选择器，完全信任 Tailwind Preflight 内置重置。

### 踩坑 3：致远 DEE REST 适配器 Body 发送空白
- **现象**：DEE REST 适配器中引用 `${施工号}` 无法直接从 Document 读取 XML 节点，导致发送 0 字节空 Body 并返回 400 错误。
- **解决**：在 DEE 中插入【脚本适配器】，使用 Groovy 脚本遍历 Document 生成 JSON 字符串并放入参数容器 (`setParam(document, "jsonBody", jsonBody)`)，REST 适配器引用 `${jsonBody}` 传输。
